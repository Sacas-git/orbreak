## 2. 方針

- **ジャム版＝ORBREAK の縦切り試作**。本制作（ラン12ステージ、メタ進行、スマホ版）はジャム後。
- **提出形式は Web（HTML5）を最優先**。投票者はブラウザで遊べるゲームを圧倒的に多く遊ぶ。Windows 版は余力があれば。
- **テーマ解釈を加点要素にする**。テーマは11/1発表。コアのゲーム性は変えず、テーマを「惑星の個性」「破片の性質」「演出・タイトル」のどこかに反映する（下の4章）。
- **公開リポジトリ前提**。キーや個人情報をコミットしない。ライセンスは MIT（コード）、自作アセットは CC BY 4.0 を推奨。

## 3. ジャム前（〜10/31）にやってよいこと・やらないこと

公式ページには既存コードの扱いについての明記がないため、**ゲームのコードはジャム開始（日本時間 11/2 6:37）以降に新規に書く**のを安全側の方針とする。

| ジャム前にやる | ジャム開始以降にやる |
|---|---|
| 仕様書（このドキュメント一式）の整備 | Godot プロジェクトの作成とすべてのゲームコード |

| 手触りの方針・調整値の検討 | テーマ解釈の決定 |

## 4. テーマを反映する場所（テーマ発表直後に決める）

テーマ発表後、次の3つのうち **1〜2か所だけ** に反映する。全部に入れない。

| 反映先 | 例（仮のテーマ「Scale（大きさ）」の場合） |
|---|---|
| 惑星の個性（ステージのルール） | 連鎖が進むほど惑星が縮む／膨らむ |
| 破片・ボールの性質（強化） | 大連鎖で破片が巨大化する |
| 演出・タイトル・物語 | 惑星サイズの小さな星から巨大な星へ進む |

決めたら `docs/DECISIONS.md` に記録し、`docs/03_TASKS.md` の **T2T（テーマ実装）** に具体的な内容を書き込む。

## 5. ジャム版のスコープ

`docs/03_TASKS.md` で **【J】** が付いたタスクがジャム版の必須。付いていないものはジャム後。

### ジャム版に入れるもの
- 円形フィールド、パドル、ボール、回転する惑星（M1 全部）
- 破片の倍々連鎖、スタンと連打復帰、再生ブロック、クリア／失敗
- 強化：10種のうち **6種**（shard_plus、shard_range、chain_boost、wide_paddle、multiball、pierce）
- ステージ：**3ステージ＋ボス風の最終ステージ1つ**（ボスの特殊挙動は1種のみ、または強いコアだけでも可）
- エンドレスモード（スコアアタック。ローカルのハイスコア保存）
- 最小限の演出（画面揺れ、倍率ポップ、音階が上がる破壊SE、BGM 1曲）
- タイトル、リザルト、最小限の設定（音量、画面揺れ）
- 遊び方が分かる 15秒程度の操作説明（最初のステージに文字で表示）
- テーマ要素

### ジャム版に入れないもの
- スマホ書き出し、広告・課金、メタ進行、ランキング、デイリー、ボス3種、強化40種

## 6. 4週間のスケジュール（週10〜15時間想定）

| 週 | 日付（2026年） | 目標 | 対応タスク |
|---|---|---|---|
| 0 | 11/2（月）朝〜 | テーマ確認、解釈を決める、プロジェクト準備（リポジトリは作成済み） | T00〜T02、テーマ決定 |
| 1 | 11/2〜11/8 | **手触りの核**：パドル、ボール、惑星、衝突。週末に触って調整 | T10〜T14 |
| 2 | 11/9〜11/15 | **連鎖**：得点、破片、スタン、再生、クリア判定。Web 書き出し確認 | T20〜T24、T29（Web のみ） |
| 3 | 11/16〜11/22 | **ゲームにする**：強化6種、ステージ4つ、エンドレス、テーマ実装 | T25〜T26、T2T |
| 4 | 11/23〜11/30 | **仕上げ**：演出、音、画面遷移、説明、テストプレイ、itch.io ページ作成、提出 | T27、T28、T2S |
| 予備 | 12/1（火） | 予備日。新機能は入れない | |

**週2の終わり（11/15）に Web 版で連鎖まで遊べること** を最重要の中間目標にする。遅れたら週3のスコープ（ステージ数、強化数）を削る。

## 8. 投票カテゴリ別の狙い

| カテゴリ | 狙い |

| Gameplay | 打ち返しの手触りと倍々連鎖。ここに一番時間を使う |
